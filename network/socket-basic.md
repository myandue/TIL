# 소켓 기초 & 블로킹 TCP 에코 서버

## 1. 소켓
- fd(파일 디스크립터): 실제 파일을 관리하는 주체(운영체제)가 지급해주는 해당 파일의 번호(정수). 우리는 이 번호표를 갖고 해당 파일에 할 동작을 운영체제에게 요청한다. (ex. 3번 파일 읽어주세요. 3번 파일에 "hello" 써주세요.)
- 소켓: fd(번호표)가 가리키는 실제 객체. 네트워크 통신 전용으로 커널이 만든 물건. - 안에 송신/수신 버퍼, 상대방 주소, 프로토콜 상태(TCP 연결 정보) 같은 것들이 들어있다.
- 즉, 커널(운영체제) 안에 소켓(자원, 통신 객체)을 하나 만들고 그것을 가리키는 번호표(fd)를 우리에게 전달해주는 것이다. 우리는 fd를 통해 소켓을 다룬다.

## 2. 서버가 연결을 만드는 단계
`socket -> bind -> listen -> accept -> read/write -> close`
- `socket()`: 전화기를 하나 개통한다. 번호표(fd) 발급.
- `bind()`: 내 주소(내 IP:포트)와 `socket`을 연결한다.
- `listen()`: 전화 받을 준비를 완료한다. 서버 대기 중.
- `accept()`: 전화를 받아서 해당 손님 전용 통화회선(새 번호표(fd))를 돌려준다. 
- `read` / `write`: 해당 손님이 보낸 것을 읽고 쓴다.
- `close()`: 회선을 끊고 종료한다.

## 3. 짚고 갈 것들
- `sockaddr_in`
    - `sin_family`: 주소종류(`AF_INET`=IPv4)
    - `sin_addr`: IP(`INADDR_ANY`= 모든 랜 카드로 받기)
    - `sin_port`: 포트
- `memset`으로 `sockaddr_in` 구조체(`addr`)를 0으로 초기화: `sin_zero` 등 안 쓰는 칸 쓰레기값 방지
- `htons()`: 네트워크는 바이트 순서를 빅엔디안으로 보내기로 약속 -> 내 컴퓨터(host) 순서를 네트워크(network) 순서로 변환. (host to network short)
- `listen_fd` vs `client_fd`: 전자는 대표번호, 후자는 accept가 준 손님 전용 통화회선. read/write는 `client_fd`로 한다.

## 4. 블로킹(blocking)
- `read()`가 블로킹: 읽을 데이터가 없으면 리턴 하지 않고 그 줄에서 멈춰 기다린다. 데이터 오면 깨어나서 리턴.
- issue: 한 프로세스는 한 번에 하나의 블로킹 대기에만 묶임 -> A를 기다리는 동안 B, C는 전부 방치.

## 5. 이 서버의 두 가지 한계
- 한계 ①: `accept`가 루프 밖 한 번뿐 -> 손님 하나 끝나면 `while`(루프) 탈출 -> `return 0` -> 서버 프로세스 종료 (=재접속하려면 서버 재실행)
- 한계 ②: 첫 손님과 `while` 중이면 `accept`가 다시 불리지 않고 `read`에서 블로킹 -> 두 번째 손님을 동시에 받지 못함. TCP 연결 자체는 성립하지만 서버가 `accept`/`read`를 해주지 않아 응답 없이 방치된다.
