# 스택 vs 힙 메모리

## 메모리
- 프로그램 실행 -> OS가 해당 프로그램에 메모리 한 덩어리 부여 -> 해당 메모리를 스택/힙 등으로 구획을 나눔

## 스택 (자동)
- 함수 호출에 묶인  LIFO 구조 (프레임 push/pop)
- 지역 변수가 해당 메모리에 보관됨
- 스코프가 끝나면 자동으로 정리됨
- 빠르지만 크기 제한이 있음
- LIFO(Last In First Out): 나중에 부른 함수가 먼저 끝남

## 힙 (수동)
- 자유 메모리 풀 (관리자가 빈자리를 찾아줌)
- `new`로 할당
- 수동으로 정리해야함. 하지 않으면 메모리 누수(창고가 꽉 참).
- 수명 스코프에 묶이지 않아 생명주기가 길다.
- 순차적으로 쌓이는 것이 아니라 자유 창고이기 때문에 느리지만 크기가 큼.

## 선택
- 스코프 안에서만 쓸거면 스택메모리를 사용
- 스코프 밖에서도 사용해야한다면 힙메모리를 사용

> 26.09.15 여전히 스택과 힙을 설명하지 못하길래 다시 백지에서 기록함

- 스택과 힙은 RAM에 있는 메모리이며 프로세스가 점유한다. 
- 스택은 LIFO로 프레임을 할당/해제한다. 즉, 프레임을 순차적으로 쌓고 순차적으로 처리하는 것이다. 때문에, 할당/해제가 그저 다음 프레임으로의 포인터 이동일뿐이며 덕분에 할당/해제가 빠르게 이루어지며 자동이다.
- 스택은 메모리가 작고, 말 그대로 프레임을 쌓으며 처리하기 때문에 무한(과도한)재귀를 돌게 될 경우에 프레임이 메모리를 초과해 스택오버플로우가 발생할 수 있다. (재귀는 호출할 때마다 프레임을 쌓는다)
- 힙의 경우 메모리가 크지만 객체를 할당 할 때, 해당 객체의 사이즈에 맞는 위치를 찾고 그 위치에 할당한다. 그렇게 빈 공간을 탐색해야하기 때문에 할당/해제에 비용이 많이 든다. 
- 힙의 객체 할당/해제는 수동으로 관리해주어야하며, 해제하지 않을 시에는 메모리 누수가 발생할 수 있다. 
- 예로, 힙 메모리에 객체가 존재하고 해당 객체를 가리키는 포인터 변수는 스택 메모리에 있을 경우, 그 포인터 변수를 제거하게 되면 힙 메모리에 있던 실제 객체는 그저 떠돌게 된다. `unique_ptr`의 경우 해당 포인터가 사라질 때 그 포인터가 가리키는 실제 객체 또한 제거시킨다. 그래서 수동 관리 없이 메모리를 관리해줄 수 있다. 
- 위 예시와 같은 '스택에 관리자 + 힙에 실제 데이터'에 해당하는 또 다른 자료구조가 `vector`이다. `vector` 객체(힙 주소, size, capacity로 구성)는 스택에 존재하며, 실제 배열은 힙에 존재한다.
