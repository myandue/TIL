> 26.09.16 자료구조의 트레이드오프를 파악하기 위해 각 자료구조를 알아본다.
<br>
> `vector`, `linked_list`, `map`, `unordered_map` 에 대해 공부하고 정리한다.

- 먼저, 자료구조는 크게 '순서 기반(sequence)'과 '키 기반(associative)'으로 구분해 볼 수 있다. 
- '순서 기반'은 '몇 번째'라는 위치가 있으며 `vector`, `list`가 여기에 해당된다. '키 기반'은 위치가 아니라 '키'로 저장 및 조회되며 `unordered_map`, `map`이 여기에 해당된다.

### vector
- `vector`는 연속 메모리에 원소를 나열한다.
- 요소들이 물리적으로 연속돼있기때문에 인덱스로 값을 조회할 때 빠르다.(O(1)) '배열 객체 주소 + 인덱스'를 통해 한 번에 요소의 주소를 찾을 수 있다. 값으로 찾아야할 때는 다 훑어야하기 때문에 O(N)의 시간이 소요된다.
- 물리적으로 연속돼있단 특징으로 인해 캐싱에 유리하다. (캐시는 캐시라인(연속된 바이트)으로 캐싱하기때문). 즉, 순회의 빈도가 잦을 때 `vector`가 유리하다.
- 배열 객체의 주소, 사이즈 등 메타데이터는 스택메모리에, 실제 배열 객체는 힙메모리에 존재한다.

### list
- `linked-list`는 노드가 메모리에 흩어져있고 그것들이 포인터로 연결되어 있다. 
- 특정 위치의 삽입/삭제가 빠르다.(O(1)) 포인터만을 교체해주면 되기 때문이다.
- `vector`와 반대로 물리적으로 흩어져있기 때문에 캐싱에 불리하다.
- 실무에서 `list`가 `vector` 대비 쓰일 일은 잘 없지만, 특정 위치의 삽입/삭제가 빈번하다면 이 때는 `list`가 유리하다.

### unordered_map
- `unordered_map`은 힙메모리에 '버킷 배열'을 두고있다. 그리고 그 '버킷 배열'의 주소를 스택메모리에 갖고있다. 
- 'key-value' 형태로 데이터를 보관하는데, key를 hash 함수로 돌린 값을 '버킷 수'로 나눈 나머지값이 버킷 배열의 인덱스가 된다. 그리고 해당 인덱스에서는 실제 'key-value 노드'를 가리키는 주소를 값으로 갖고있다. 
- `vector`와 마찬가지로 '배열의 주소값 + 인덱스'의 형태로 특정 값에 바로 도달할 수 있기 때문에 특정 값 조회가 빠르다.(O(1)) `vector`에서 인덱스는 그냥 정수였다면, `unordered_map`에서는 '(key 해시 값) % 버킷 수'(= 버킷 인덱스) 인 셈이다.
- 순회는 버킷 배열을 훑기 때문에 O(N)이며 노드가 흩어져있기 때문에 캐싱에는 불리하다.
- 다른 key일지라도 '(key 해시 값) % 버킷 수'가 같을 수 있으며, 이 경우를 '해시 충돌(collision)'이라 한다. 이럴 때에는, 해당 버킷에 충돌된 값들이 같이 들어간다(체이닝-같은 버킷에 리스트). 
- 충돌의 빈도가 잦아지면(load factor가 임계치를 넘어설 때), 특정값 조회 그 자체는 O(1)일지라도 해당 버킷에 값이 여럿 있을 경우 최악으로는 선형 탐색인 O(N)이 될 수 있다. 이럴 때에는 버킷 수를 늘려 rehash를 진행하는데, 버킷수가 변동되기 때문에 버킷 인덱스 계산을 모두 새로 하고 재배치를 진행해야한다.
- 참고) `load factor` = 원소수 ÷ 버킷수. 임계치는 기본이 1.0인데, 이 말은 '원소수가 버킷수를 넘어설 때' rehash가 발생함을 의미한다.
- 삽입시 평소에는 O(1), rehash가 걸리는 순간에는 O(N) 스파이크. 후자가 드문 케이스이기 때문에 삽입은 평균 O(1).

### map
- `map`은 '균형 이진 탐색 트리(BST)'의 형태이다. 'key'의 정렬에 따라 트리에 값이 배치된다.
- 흩어져 있는 노드간 포인터로 연결된 구조이기 때문에, 캐싱에 불리하다. 
- 특정값 조회는 해당 키를 찾기 위해 트리에 대한 이진 탐색으로 진행된다.(O(logN))
- 삽입/삭제 시 균형 유지를 위해 국소적 재배치(회전)가 일어나지만, 변경 경로상 몇 노드만 발생한다.(O(logN))

### 선택 기준
- 순회가 잦다 -> vector(캐시)
- 특정 키로 조회가 잦다 -> unordered_map (평균 O(1))
- 정렬 순서·범위 검색·안정적 O(logN) 이 필요하다 -> map
- 특정 위치의 삽입·삭제가 잦다 -> list (O(1))
