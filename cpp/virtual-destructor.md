# 가상 소멸자 + vtable/vptr (다형성 내부 동작)

### 가상 소멸자
- 전제) 부모 클래스를 확장하여 자식 클래스를 선언하고 해당 자식 클래스의 객체를 부모 포인터로 생성하였을 때 
- 문제) 소멸자가 virtual 소멸자가 아니라면 해당 포인터를 delete 할 때 부모 객체에 대한 소멸자만이 호출되어 실제 자식 객체에 대한 소멸자 호출은 누락되고, 그로써 자식이 할당한 자원이 정리되지 않아 메모리 누수로 이어진다.
- 해결) 때문에, 부모 클래스 내에서 소멸자 선언시 `virtual`을 붙여줌으로써, 자식 클래스 객체 소멸자 호출 누락을 막아준다. `delete` -> `자식 객체 소멸자 호출` -> `부모 객체 소멸자 호출`

### 비용 및 트레이드오프 (`vptr`, `vtable`)
- `virtual`을 붙여줌으로써 메모리 누수를 방지할 수 있지만, 무분별한 `virtual` 선언은 조심해야한다. 위에 선언한 전제에 해당하지 않는다면 굳이 할 필요 없다는 것이다.
- 일반적인 클래스 선언의 경우에는, 컴파일 시 클래스 내부에 있는 함수는 본인 고유의 주소를 갖게된다. 즉, `Potion` 클래스는 컴파일 시 `Potion` 클래스의 `use()` 함수가 본인의 주소를 갖게되고, `Potion` 객체를 생성하면 해당 객체의 `use()` 함수를 호출할 때에 바로 그 주소를 찾아가 실행하는 것이다.
- 하지만 `virtual` 함수가 있는 클래스의 객체라면, 할당받은 `vptr`를 따라가 `vtable`을 찾아야하고, 거기서 실제 함수의 주소를 찾아내야한다. 이와 같은 이유로 `virtual` 할당에는 비용이 발생하고, 때문에 무분별한 `virtual` 남용을 하지 않는 것이 좋다. 
- 이와 같은 `vptr`, `vtable`은 클래스 내에 어디 한 군데에라도 `virtual`이 선언된다면 생기는 요소들이다.
